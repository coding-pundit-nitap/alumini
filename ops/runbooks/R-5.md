# R-5 — PostgreSQL pressure

**Alerts:** `PostgresDown` (page) · `PostgresConnectionsHigh`, `DbPoolSaturated` (ticket).

## What it means

- `PostgresDown`: the exporter cannot connect; the app's readiness fails too ([R-1](./R-1.md)).
- `PostgresConnectionsHigh`: more than 85 % of `max_connections` are in use.
- `DbPoolSaturated`: callers in web or worker have waited for a pooled connection for 5 minutes (pool `max` is 5 in the worker; the web pool is per instance).

## Check first

1. Connections and what they do:
   ```sql
   SELECT state, wait_event_type, count(*), max(now() - xact_start) AS oldest_xact
   FROM pg_stat_activity WHERE datname = current_database() GROUP BY 1, 2;
   ```
2. Long or idle-in-transaction sessions and lock waits:
   ```sql
   SELECT pid, now() - xact_start AS age, state, left(query, 120)
   FROM pg_stat_activity WHERE xact_start < now() - interval '1 minute' ORDER BY age DESC;
   ```
3. Pool size × number of instances against `max_connections`. Did a deploy add instances?
4. A migration or backfill running right now?

## Mitigate

- Terminate the offending session: `SELECT pg_terminate_backend(<pid>);`
- Pause a backfill; cancel a stuck migration.
- Too many instances for the server → reduce pool size or add a pooler.

## Escalate

Cannot connect at all →.3 (database recovery).

## Resolved when

`db_pool_connections{state="waiting"}` is 0 and connections are under 70 % for 15 minutes.
