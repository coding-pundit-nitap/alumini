# R-2 — API errors (5xx) and latency

**Alerts:** `HighErrorRate` (page), `HighLatencyP95` (ticket), `HighLatencyP95Sustained` (page).

## What it means

More than 2 % of `/api` requests fail with 5xx, or p95 latency is above 500 ms, with at least 50 requests in the window. Readiness and instance-down alerts inhibit these, so if this fired the instance itself is up.

## Check first

1. **Error tracker:** the newest error class, and its release. A new class right after a deploy is the usual cause.
2. **Grafana → API (RED per route):** which route is failing or slow? One route points at a feature; all routes point at a dependency.
3. Logs: `event="http.request.failed"` at `level="error"` — each line has `request_id`, `path` and `code`.
4. **Grafana → Async:** "DB pool" waiting > 0 or transaction retries rising means PostgreSQL pressure → [R-5](./R-5.md).
5. Redis: cache Redis down slows rate limiting and hints → [R-6](./R-6.md).

## Mitigate

- Release-correlated → roll back.
- One feature failing → turn it off if it has a switch; otherwise roll back.
- Load → tighten rate limits.
- A slow query → add the missing index or terminate the runaway query ([R-5](./R-5.md)).

## Escalate

Data integrity suspected (wrong data written, not just errors) →.

## Resolved when

The 5xx ratio is under 2 % and p95 under 500 ms for 15 minutes.
